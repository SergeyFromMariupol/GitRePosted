# Обслуживание новой установки

Стандартные пути установщика:

| Назначение | Путь |
|---|---|
| Код установщика | `/opt/gitreposted-installer` |
| Приложение и releases | `/opt/gitreposted` |
| Node.js | `/opt/gitreposted-node` |
| Защищённая конфигурация | `/etc/gitreposted/config.json` |
| Данные приложения | `/var/lib/gitreposted` |
| Состояние установки | `/var/lib/gitreposted-installer` |
| Журналы | `/var/log/gitreposted` |
| ACME webroot | `/var/www/gitreposted-acme` |

Рабочий процесс запускается отдельным системным пользователем `gitreposted`.
Проверяйте состояние systemd-служб и журнал, не публикуя их без редактирования
токенов, идентификаторов пользователей и содержимого сообщений. `GET /health`
показывает ответ HTTP-процесса; это не доказательство доставки или готовности
базы. `/control/` — интерфейс управления; API требует авторизации.

В runtime используется один bridge-процесс. Не создавайте второй worker,
cron или копию активной базы для параллельной доставки. При переносе сначала
остановите старые потребители, подготовьте согласованный backup приложения,
настроек, MySQL и данных, затем проверьте новый сервер. Этот выпуск не содержит
автоматического переноса или обновления существующей установки.

Очередь использует состояния `pending`, `sending`, `completed`, `failed` и
`uncertain`. При неоднозначном результате сначала сверяют целевой канал и
сохранённые идентификаторы сообщений. Нельзя просто перевести `uncertain`
обратно в `pending`: это может продублировать публикацию. Завершённые части
доставки и историю идемпотентности нельзя стирать ради повторной попытки.

Перед обновлением сохраните согласованный backup вне webroot и проверьте
возможность восстановления. Секреты, БД и media не входят в release archive.
Резервная копия только исходного кода не восстанавливает каналы, маршруты и
очередь. Не выкладывайте backup в публичный Git.

TLS-сертификат и его продление проверяются отдельно. Публичный CA-файл в
payload не содержит private key. Если он используется для соединений с МАКС,
следите за сроком действия и доверенной цепочкой; проверку TLS не отключайте.

При сбое установки используйте сохранённое состояние того же мастера и
безопасный код ошибки. Не удаляйте системные каталоги, конфигурацию, DB или
сертификаты вручную для «чистой повторной попытки».
