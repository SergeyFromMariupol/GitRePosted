# Конфигурация

Установщик хранит конфигурацию вне приложения и webroot. Точные пути новой
установки и службы перечислены в [OPERATIONS.md](OPERATIONS.md). Файл
настроек содержит секреты; его нельзя прикладывать к issue или отдавать через
nginx. Examples в payload/src/ содержат только шаблоны и не используются как
готовые настройки.

В мастере выбираются логин и пароль администратора, часовой пояс, токены
включённых ботов и необязательная hCaptcha. Пароль сохраняется в виде hash;
секреты webhook создаются отдельно. Токен одного бота нельзя одновременно
обслуживать двумя установками. Переключение существующего webhook требует
явного согласия.

При совместной установке с GitPosted каждый проект получает собственных ботов
и токены. Один и тот же канал можно подключить к обоим приложениям, добавив
в него обоих ботов с нужными правами. У каждого проекта отдельная панель,
логин, конфигурация, база и системный пользователь; настройки GitRePosted
не становятся настройками GitPosted.

Telegram и МАКС независимы: выбранная платформа получает свой webhook и
разрешение на обработку событий. Не выбранная платформа остаётся выключенной.
Служба не должна начинать доставку до завершения проверок установки.
Публичные ссылки на ботов берутся из настроек этой установки; отсутствующие
или выключенные боты не должны вести к чужим каналам.

## Подключение ботов после установки

Если платформу пропустили в мастере, откройте «Настройки бота» в панели:

1. Выберите Telegram или МАКС, включите платформу, вставьте её токен и укажите
   ссылку именно на своего бота. Сохранённый секрет уведомлений можно оставить;
   пустое поле с пометкой о настроенном секрете его не удаляет.
2. Включите «Публичный доступ через …-бота» для работы меню и каналов.
   При выключенном доступе бот не разрешает эти действия всем аккаунтам;
   назначение административных прав сервиса этот переключатель не обходит.
3. Сохраните, нажмите «Применить и перезапустить» и войдите в панель снова.
4. Нажмите «Подключить webhook» для добавленного бота. Если он уже подключён
   к другому сервису, перенос потребует отдельного подтверждения.
5. Откройте бота и выполните добавление каналов и создание пересылки по
   [пошаговой инструкции](INSTALLATION.md#5-добавьте-каналы).

Сохранённые и активные настройки различаются до перезапуска; подключение
webhook до применения настроек блокируется. Перезапуск общий для приложения,
поэтому кратко затронет обе платформы. Затем проверьте выделенный тестовый канал.

## Домен и каналы

Домен задаётся в команде `--host` либо на шаге «Сервер» до запуска финального
задания мастера. Две новые установки rc.8 и новее могут использовать общий IP,
общий домен или разные домены. У GitRePosted постоянный путь `/GitRePosted`,
у GitPosted — `/GitPosted`; админки находятся под `/control/` каждого пути.
Без `--host` второй проект наследует текущий проверенный адрес первого.
Для другого домена передайте его в команде либо выберите в мастере до настройки
ботов. Рядом со старой корневой установкой rc.7 и ниже второй проект по-прежнему
требует отдельный явный домен; автоматической миграции старого режима нет.
DNS-запись у своего провайдера меняет пользователь. Текущий
установщик проверяет единственный публичный IPv4: для выбранного имени не
должно быть дополнительных A или AAAA. HTTPS, сайт и webhook настраиваются
автоматически после проверки. Подробности — в
[разделе о домене](INSTALLATION.md#3-подключите-домен-если-он-нужен).

После завершения мастер закрыт; отдельной смены домена в панели нет.
Изменение одного PUBLIC_BASE_URL не перенастраивает DNS, сертификат, сайт
и webhook. Запуск `--resume --host …` завершённую установку не переносит.
При подготовке домена сохраняются его маршруты и владелец сертификата, в том
числе при повторе или временном сбое. В новом режиме соседний проект может
использовать тот же адрес под своим постоянным путём и готовым HTTPS.
Подробности и команды — в [совместной установке](INSTALLATION.md#два-проекта-на-одном-сервере).
Продление запускает отдельный timer проекта и обрабатывает только сертификаты,
владельцем которых является этот проект, под общей блокировкой. Сертификат
общего адреса продлевает первый владелец; второй проект не создаёт его копию.
Дополнительное случайное ожидание Certbot
выключено: сдвиг времени уже задаётся timer. На тестовой совместной установке
проверены HTTPS, собственное продление и certbot dry-run; границы приёмки — в
[TESTING.md](TESTING.md#выпуск-rc6-два-проекта-на-одном-сервере).

Права на канал подтверждаются в боте: пользователь добавляет своего бота
администратором с правом публикации и пересылает ему публикацию из канала.
Проверяются права и пользователя, и бота. Для межплатформенных маршрутов
аккаунты связываются шестизначным кодом; доступ к каналам проверяется отдельно.

## Ручные параметры и совместимость

В payload/src/.env.example перечислены совместимые параметры Node runtime:
адрес сервера, MySQL, provider endpoints, таймауты, retries и local-file
mapping. Это справочный формат для ручных конфигураций; JSON-конфигурацию
установщика нельзя заменять примером env. Меняйте действующую установку через
её панель и документированные процедуры, сохраняя формат конфигурации.

Облачный Telegram Bot API используется по умолчанию. Локальный Bot API
поддерживается приложением при отдельной ручной подготовке сервиса и безопасного
mapping каталогов; мастер его не устанавливает. Нельзя включать cloud и local
потребителей одного токена одновременно. При local mode произвольный путь на
сервере не является допустимым media-файлом: требуется containment после
realpath, без symlink escape.

hCaptcha необязательна для установки. При включении нужны оба ключа для
вашего публичного адреса. Отключение captcha не отключает проверку пароля,
сессию или ограничения попыток входа. Закрепляйте версию выпуска и сверяйте
контракт runtime с установщиком перед ручным изменением формата настроек.

JSON-конфигурация обязана содержать строки `0` или `1` для `TELEGRAM_ENABLED`,
`MAX_ENABLED`, `HCAPTCHA_ENABLED` и `GITREPOSTED_WORKERS_ENABLED`. Отсутствующий
переключатель останавливает запуск. Legacy env сохраняет прежние defaults.

На Ubuntu запись конфигурации подтверждает и файл, и каталог. Если замена
файла уже произошла, но подтверждение диска завершилось ошибкой, API возвращает
503 `CONFIG_DURABILITY_UNCONFIRMED`. Настройки уже могут быть изменены:
перечитайте состояние, проверьте диск и не повторяйте запрос автоматически.
После такой смены пароля действуют перечитанные credentials, старые сессии
отзываются. Если перечитать конфигурацию невозможно, административный доступ
закрывается до устранения ошибки; прежний пароль автоматически не возвращается.
