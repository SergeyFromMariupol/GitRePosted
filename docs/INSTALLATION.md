# Новая установка

Инструкция ведёт от подготовки сервера до первой пересылки. Нужен Ubuntu Server
24.04 с systemd, публичным IPv4 и доступом root; поддерживаются x86_64 и arm64.
Порты 80/443 должны быть доступны извне. Подходит чистый сервер либо завершённая
установка GitPosted, чьё состояние и общий стек удалось проверить. Произвольные
существующие сайты и базы установщик не подхватывает.
Статус выпуска и фактически выполненные проверки — в [TESTING.md](TESTING.md).

## Изменения rc.7

Выпуск rc.7 продолжает продление остальных собственных сертификатов после
ошибки одного адреса и корректно проверяет новое задание домена при потере
ответа мастера. В обоих установщиках `needrestart` только перечисляет службы,
которым нужен перезапуск; собственные действия пакетных скриптов проверяются
отдельно. В обоих установщиках исправлено завершение групп дочерних процессов команд
при ошибке или таймауте. CLI bootstrap обоих проектов обрабатывает `SIGTERM`
и `SIGHUP` с очисткой процессов и кодом `BOOTSTRAP_INTERRUPTED`.
Проверки rc.7 завершены: 44/44 Linux suites, Chrome GP48/48 и GRP67/67,
изолированные HTTP/PHP/Unix/MySQL сценарии GP6/6. Историческая
приёмка rc.6 не заменяет их результаты.

## 1. Подготовьте ботов и выберите адрес

Создайте собственных ботов на нужных площадках и получите их токены. Можно
использовать Telegram, МАКС, обе платформы или установить панель без ботов
и подключить их позже. Токены вводятся в HTTPS-мастере, в команду сервера
их вставлять не нужно. Адрес панели и токены каждой установки свои.

Для новых установок домен необязателен: установщик умеет подготовить доверенный
HTTPS по публичному IP. Если хотите свой домен, сначала настройте DNS по разделу
ниже. Его можно выбрать до запуска финальной установки на шаге «Сервер» мастера.
Вторая новая установка может использовать тот же IP или домен: её постоянный
путь `/GitRePosted/` не пересекается с `/GitPosted/`. Для другого домена передайте
его через `--host`. Условия для старого корневого режима указаны ниже.

## 2. Запустите одну команду

Войдите на сервер по SSH и выполните команду первой установки:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitRePosted/main/install.sh | sudo bash
```

Если вы уже вошли как root, используйте `bash` вместо `sudo bash`.
Загрузчик скачает закреплённый опубликованный архив, проверит SHA256 и
подготовит системные компоненты, MySQL, приложение и HTTPS. Дождитесь ссылки
на мастер: `/GitRePosted/install/#setup=…`. Она даёт доступ к первоначальной настройке;
не публикуйте её. Отдельно придумывать код доступа не требуется.

По умолчанию определяется публичный IPv4. При необходимости замените
`sudo bash` на `sudo bash -s -- --public-ip YOUR_PUBLIC_IPV4`, подставив IP
своего сервера. Ручная установка из архива описана ниже.

## Два проекта на одном сервере

Начиная с **0.1.0-rc.8**, новые установки обоих проектов используют постоянные
пути `/GitPosted/` и `/GitRePosted/`. Можно начать с любого проекта: полностью
завершите его браузерный мастер, затем установите второй.

| Размещение | GitPosted | GitRePosted |
|---|---|---|
| Общий IP без домена | `https://IP/GitPosted/control/` | `https://IP/GitRePosted/control/` |
| Общий домен | `https://example.org/GitPosted/control/` | `https://example.org/GitRePosted/control/` |
| Разные домены | `https://posted.example.org/GitPosted/control/` | `https://reposted.example.org/GitRePosted/control/` |

`IP` и домены в таблице замените своими. Без `--host` первая установка выбирает
публичный IP. Вторая без `--host` использует текущий проверенный адрес первого
проекта. Для разных доменов передайте каждому свой `--host`; для общего домена
укажите одинаковое имя либо не передавайте его второй установке. Все выбранные
имена должны иметь A-запись на IPv4 сервера. Установщик не меняет DNS.

Команды для общего IP или наследования адреса:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitPosted/main/install.sh | sudo bash
```

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitRePosted/main/install.sh | sudo bash
```

Для домена добавьте к нужной команде `-s -- --host example.org` после `sudo bash`.
Для разных доменов укажите разные имена. Для предварительной проверки добавьте
`--dry-run`: она проверяет совместимость, но не заменяет установку зависимостей.

Главная `/` показывает ссылки на размещённые на этом адресе приложения.
У каждого проекта свой мастер (`/GitPosted/install/` или `/GitRePosted/install/`),
логин, пароль и админка. Персональная ссылка одного проекта не открывает другой.
Токены ботов должны быть разными; в каналы можно добавить обоих ботов с нужными
правами. Telegram и МАКС можно пропустить и подключить позже.

nginx, MySQL и PHP общие; базы `GitPosted`/`GitRePosted`, системные пользователи,
данные, конфигурации, cookies и службы приложений разделены. Один HTTPS-сертификат
общего адреса обслуживается установщиком, который первым занял этот адрес;
второй использует его. Продление выполняется автоматически. Приложения слушают
только внутренние порты, снаружи доступны через общий nginx.

Установщик проверяет соседний проект и использует общую блокировку. При
`SHARED_INSTALL_BUSY` дождитесь другого системного шага. При прерывании
продолжайте именно свой проект через `--resume`, а браузерное задание — в его
мастере. Не удаляйте state-файлы, блокировки и базы для обхода проверки.
Сторонние сайты или произвольная существующая MySQL этим режимом не подхватываются.

**Старые установки rc.7 и ниже:** корневые адреса `/control/` сохраняются.
Повторный загрузчик не обновляет и не переносит готовое приложение. Рядом с
проверенной старой установкой второй проект требует отдельный явный домен и
тоже использует прежний корневой режим. Общий адрес с постоянными путями
предназначен для двух новых установок rc.8 и новее; автоматической миграции
готовых установок в этом выпуске нет.

## 3. Подключите домен, если он нужен

Допустим, ваш домен — `example.com`, а сервис будет на `posts.example.com`.
В панели DNS-провайдера добавьте запись:

| Тип | Имя | Значение |
|---|---|---|
| A | posts | YOUR_PUBLIC_IPV4 |

`example.com` и `YOUR_PUBLIC_IPV4` — примеры: замените их собственным доменом
и IPv4 сервера. Для корня домена провайдер обычно использует имя `@`.
Текущий установщик требует, чтобы выбранное имя разрешалось только в этот
IPv4: удалите для этого имени лишние A-записи и AAAA-запись. DNS-прокси,
подменяющий адрес сервера, для этой проверки нужно отключить. DNS-записи
пользователь меняет у своего провайдера; установщик их не создаёт.

После обновления DNS откройте первый шаг мастера «Сервер», раскройте
«Подключить домен», введите имя без `https://`, пути и порта и нажмите
«Проверить домен и настроить HTTPS». Email необязателен. Поле мастера принимает
домен с обычной латинской зоной, например .ru или .com. Кириллическое имя
передаётся в punycode; если сама зона тоже кодируется через `xn--` (например
.рф), укажите полное punycode-имя через `--host` при первом запуске команды,
как в примере ниже. Дождитесь сообщения «Домен готов» и продолжайте в той же
вкладке, если подключаете домен через мастер. Установщик сам проверит DNS, получит сертификат,
настроит сайт и использует домен для webhook выбранных ботов. Продление
сертификата выполняется автоматически.

Если DNS уже готов до запуска команды, можно сразу установить с доменом:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitRePosted/main/install.sh | sudo bash -s -- --host posts.example.com
```

Выберите один способ: домен в команде либо подключение домена в первом шаге
мастера. После запуска финального задания установки сменить адрес в мастере
уже нельзя. После завершения отдельной кнопки смены домена в панели нет;
такой перенос требует отдельной настройки DNS, HTTPS, сайта и webhook.
Повторный запуск с `--host` на завершённой установке адрес не меняет.

## 4. Завершите мастер

1. Откройте персональную HTTPS-ссылку из терминала. На первом шаге выберите
   адрес по IP или подключите домен, затем переходите дальше.
2. Задайте логин и отдельный пароль администратора панели, минимум 12 символов,
   выберите часовой пояс.
3. Включите выбранные платформы, вставьте токены и проверьте их кнопками мастера.
   Telegram и МАКС независимы; отсутствующего бота можно пропустить.
4. Если у бота уже есть webhook другого сервиса, перенос требует вашего
   подтверждения. Подтверждайте только намеренный перенос: прежний сервис
   перестанет получать события этого бота.
5. При желании включите hCaptcha. API ID/hash и вход по номеру Telegram для
   установки не требуются.
6. Проверьте итоговые настройки и нажмите «Установить GitRePosted». Дождитесь
   завершения всех этапов.

Установщик сам создаёт базу и секреты, регистрирует и проверяет webhook,
настраивает меню `/start`, включает обработку выбранных платформ и закрывает
мастер. Панель откроется по `https://ВАШ-АДРЕС/GitRePosted/control/`. Логин и пароль панели
вы задали на втором шаге. Мастер не создаёт самих ботов, каналы или маршруты.

## 5. Добавьте каналы

Для каждой подключённой платформы выполните следующие действия:

1. В Telegram или МАКС добавьте **своего бота** администратором нужного канала
   с правом публикации. Ваш личный аккаунт также должен быть владельцем или
   администратором этого канала.
2. Откройте личный диалог со своим ботом и нажмите `/start`.
3. Выберите «Добавить канал» и перешлите боту любую публикацию из этого канала
   обычной пересылкой, сохранив канал-источник.
4. Дождитесь подтверждения: бот проверит ваши права и свои права, затем
   закрепит канал за вашим аккаунтом.
5. Повторите для каждого канала-источника и канала-получателя. Telegram-пост
   пересылайте Telegram-боту, публикацию МАКС — МАКС-боту.

Одного добавления бота администратором недостаточно для подтверждения
принадлежности канала пользователю. После подтверждения канал появится при
создании пересылки. Если проверка не прошла, исправьте указанные ботом права
и повторите добавление.

## 6. Свяжите аккаунты и создайте пересылку

Для Telegram ↔ МАКС сначала откройте «Связь аккаунтов» в одном из своих ботов,
получите шестизначный код и введите его в другом боте по подсказкам меню.
Код действует 10 минут. Используйте свои аккаунты на обеих площадках.
Связывание объединяет доступные вам каналы; права на чужие каналы оно не даёт.

Затем нажмите «Создать пересылку», выберите канал-источник и один или несколько
каналов-получателей, сохраните. Новые публикации в источнике будут передаваться
по включённому маршруту. Сначала проверьте текст, медиа и отсутствие обратного
эха в выделенных тестовых каналах, затем подключайте рабочие каналы.

Логин администратора панели и аккаунты Telegram/МАКС — разные учётные записи.
Первый посетитель `/start` не получает права администратора сервиса автоматически.
Пользователю для своих каналов нужны права владельца/администратора канала;
специальные административные права сервиса для этого не требуются при
включённом публичном доступе к боту.

## Если ботов пропустили при установке

Добавьте их через «Настройки бота» в панели: токен, включение платформы и
ссылка на своего бота → сохранить → «Применить и перезапустить» → войти снова →
«Подключить webhook». Включите публичный доступ выбранного бота: при выключенном
доступе его меню и работа с каналами закрыты для всех аккаунтов, включая
администраторов сервиса. Подробности — в
[CONFIGURATION.md](CONFIGURATION.md#подключение-ботов-после-установки).

## Ручная установка из полного архива

Получите полный архив и checksum одного выпуска на странице
[Releases](https://github.com/SergeyFromMariupol/GitRePosted/releases).
Поместите их в каталог root, недоступный другим пользователям для записи;
затем выполните в нём:

```bash
sha256sum --check gitreposted-installer.tar.gz.sha256
tar -xzf gitreposted-installer.tar.gz
sudo bash ./gitreposted-installer/bootstrap.sh --public-ip YOUR_PUBLIC_IPV4
```

Подставьте свой IPv4. Для домена с готовым DNS добавьте
`--host posts.example.com`. Отдельный bootstrap.sh без payload приложение
не устанавливает. Архивы опубликованных выпусков не заменяются исправленным
кодом; используйте выбранный проверенный выпуск.

## Если установка прервалась

Команда загрузки использует curl и Python 3. Если они отсутствуют в
минимальном образе Ubuntu, подготовьте их перед повтором команды установки:

```bash
sudo apt-get update
sudo apt-get install -y curl python3 ca-certificates
```

Для root `sudo` в этих командах можно убрать.

Если этап завершился ошибкой, сохраните безопасный код ошибки и вернитесь к
тому же мастеру. Не очищайте базу и не удаляйте очереди для повторного запуска.
Не запускайте вторую установку с токеном действующего бота без плана переноса.

Если SSH-соединение или питание прервались раньше сохранения полного пакета,
локального `/opt/gitreposted-installer/bootstrap.sh` может ещё не быть.
Повторите внешний загрузчик с продолжением:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitRePosted/main/install.sh | sudo bash -s -- --resume
```

Он использует сохранённое состояние этой установки. Если каталог состояния ещё
не успел появиться и никаких изменений нет, повторите первоначальную команду
без `--resume`. Чужие и неизвестные файлы установщик автоматически не удаляет.

Если запись каталога на диск после атомарной замены не подтверждена,
`BUNDLE_UNAVAILABLE` сообщает точный путь сохранённого прежнего пакета.
Устраните проблему диска и используйте внешний загрузчик с `--resume`.
Такие staging-каталоги не удаляются автоматически при последующих запусках;
не удаляйте их до проверки состояния диска и действующего полного пакета.

На первоначально чистом сервере продолжение ждёт завершения других операций
APT/dpkg в пределах заданного таймаута и завершает настройку прерванных пакетов.
При установке вторым общие зависимости проверяются отдельно. Даже если прерван
только собственный добавленный пакет второго проекта, состояния dpkg `iU`, `iF`
или ожидающие triggers требуют явной отдельной проверки и обслуживания
оператором. При `SHARED_PACKAGE_CHANGE_REQUIRED` проверьте APT/dpkg и состояние
первого проекта, подготовьте необходимое обслуживание, затем продолжите тот же
второй установщик. Он не запускает общее `dpkg --configure --pending` и не
переустанавливает первый проект ради исправления второго.
Файлы блокировки не удаляются; автоматическое удаление пакетов запрещено.
При `PACKAGE_MANAGER_BUSY`
дождитесь другой операции и повторите `--resume`. Повреждённую базу пакетов
установщик не обходит: сохраните безопасный код ошибки и проверьте APT/dpkg.

Режим `NEEDRESTART_MODE=l` в rc.7 предотвращает перезапуски со стороны
`needrestart`, но не отключает собственные post-install скрипты пакетов.
Изменение общих PHP/nginx/MySQL-зависимостей по-прежнему требует отдельного
обслуживания. При `SIGTERM`/`SIGHUP` bootstrap завершает дочерние процессы,
освобождает общую блокировку и возвращает `BOOTSTRAP_INTERRUPTED`; перед
`--resume` всё равно проверьте незавершённые пакеты. После принудительного
`SIGKILL`, потери питания или сбоя ядра
проверьте оставшиеся дочерние процессы, APT/dpkg, nginx, службы первого проекта
и сохранённое задание до повторного запуска. Не сбрасывайте базу и состояние
мастера вместо такой проверки.

Если ранний bootstrap прервался до мастера и конфигурации приложения,
новый выпуск загрузчика может безопасно выбрать новый подготовленный runtime,
сохранив каталог прежнего выпуска. После начала настройки приложения такой
переход запрещён. `--resume` завершённой установки не обновляет приложение
и не открывает мастер повторно.
