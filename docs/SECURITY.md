# Безопасность

Используйте отдельный сервер и собственных ботов. Мастер настройки доступен
по персональной ссылке HTTPS и закрывается после завершения установки. Это
ограничивает захват ещё не настроенного сервиса случайным посетителем. Не
пересылайте ссылку и не вводите секреты через HTTP.

Конфигурация хранится вне webroot; права ограничиваются нужным системным
пользователем. Admin password hash, session-signing secret, bot tokens,
webhook secrets и DB password — разные значения. Не передавайте их аргументами
процесса и не сохраняйте в Git. Реальные env, SQL exports, private keys,
provider sessions и logs в публичном комплекте запрещены.

Webhook проверяет секрет и размер JSON, сохраняет событие в MySQL и лишь затем
подтверждает приём. Доставка использует стабильные идентификаторы, snapshot
маршрута и продлеваемую lease. Неоднозначный ответ провайдера не является
разрешением повторной отправки. Для тестирования нужны offline transports либо
явно разрешённые реальные боты и тестовые каналы.

Установщик проверяет существующие подключения бота. Подтверждение переноса
переключает webhook и влияет на прежний сервис. Никогда не подтверждайте
перенос по привычке ради проверки токена.

Архив строится по явному allowlist, проходит проверку содержимого и включает
MANIFEST.sha256 для каждого файла. Проверка manifest обнаруживает изменения и
лишние файлы, но сама по себе не подтверждает происхождение архива: источник
загрузки и внешний SHA256 тоже должны быть доверенными. Pin release-loader
изменяется только после сборки проверенного выпуска.

Не отключайте TLS verification и не открывайте MySQL/Node backend наружу.
nginx принимает публичные HTTP(S)-запросы, а backend слушает loopback. Local
media paths требуют realpath containment. Symlink, reparse point и private
key/session содержимое отклоняются упаковщиком.

У проекта пока нет отдельного подтверждённого канала для уязвимостей. Не
создавайте публичный issue с токеном, dump или пользовательскими сообщениями;
сначала подготовьте обезличенный сценарий воспроизведения.
