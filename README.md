# GitRePosted

Бесплатный проект с открытым исходным кодом для автоматической пересылки
публикаций Telegram ↔ МАКС на своём сервере. GitRePosted и
[GitPosted](https://github.com/SergeyFromMariupol/GitPosted) созданы как свободная
альтернатива платному Telegram-боту [Posted (@posted)](https://t.me/posted):
идея управления публикациями получила развитие для Telegram и мессенджера МАКС.

Используйте для себя, команды и друзей без лицензионной платы за каждый
подключённый канал. Код распространяется по [MIT License](LICENSE); сервер и
при необходимости домен оплачивает владелец. Производительность зависит от
ресурсов сервера и ограничений API платформ.

Сайт проекта: [gitreposted.ru](https://gitreposted.ru/).

GitRePosted пересылает публикации между каналами Telegram и МАКС. Подключите
своих ботов, добавьте их администраторами каналов и настройте маршруты.
Каждая установка использует собственные токены, базу данных и панель управления.
Можно подключить одну платформу, обе или добавить ботов позже.

Исходный код: [SergeyFromMariupol/GitRePosted](https://github.com/SergeyFromMariupol/GitRePosted).

## Бесплатная альтернатива Posted для Telegram и МАКС

Если ищете «Posted бесплатно», «аналог Posted» или «Posted для МАКС», эти
проекты позволяют самостоятельно разместить инструменты публикации у себя:

- **GitPosted** — создание, оформление и планирование постов в Telegram и МАКС.
- **GitRePosted** — автоматическая пересылка между каналами, включая
  Telegram ↔ МАКС, со своими ботами и настройкой источников и получателей.

Развитие идеи Posted в этих проектах — поддержка двух платформ,
самостоятельная установка, открытый код и отсутствие лицензионной платы за
каждый канал. GitRePosted дополняет планировщик GitPosted задачами пересылки.
Это самостоятельные проекты: они не связаны с командой Posted, не используют
подписку Posted и не заявляют полную совместимость с его функциями.

**English:** GitRePosted and GitPosted are free, open-source, self-hosted
Posted alternatives for Telegram and MAX Messenger. GitRePosted handles
automatic channel relays; GitPosted handles post creation and scheduling.

## Установка

Нужен Ubuntu Server 24.04 с systemd, публичным IPv4, архитектурой
x86_64 или arm64 и доступом root. Порты 80 и 443 должны быть доступны извне.
Подходит чистый сервер либо завершённый GitPosted, установленный совместимым
пакетом и прошедший проверку. Сторонние сайты и произвольную существующую
конфигурацию MySQL установщик не подхватывает.

Команда загружает закреплённый опубликованный архив и проверяет его SHA256.
Выбранный выпуск и его контрольная сумма доступны на странице
[Releases](https://github.com/SergeyFromMariupol/GitRePosted/releases):

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitRePosted/main/install.sh | sudo bash
```

Если вы уже вошли как root, замените `sudo bash` на `bash`. Загрузчик проверяет
SHA256 закреплённого архива до распаковки и запуска. Для домена,
DNS которого уже направлен на сервер, замените `sudo bash` на
`sudo bash -s -- --host your-domain.example`. При первой установке без домена
установщик определит публичный IPv4; при необходимости передайте
`--public-ip YOUR_PUBLIC_IPV4`. Вторая новая установка без `--host` наследует адрес первого проекта;
для другого домена передайте его в `--host`.

Для ручной установки получите полный архив и SHA256 одного выпуска на
странице Releases. Старые assets rc.1 сохраняются без замены и содержат
описанную ошибку установки. Поместите оба файла выбранного исправленного
выпуска в защищённый каталог root. Следующие команды выполняются от root
в этом каталоге; проверьте checksum до распаковки и запуска:

```bash
sha256sum --check gitreposted-installer.tar.gz.sha256
tar -xzf gitreposted-installer.tar.gz
bash ./gitreposted-installer/bootstrap.sh --public-ip YOUR_PUBLIC_IPV4
```

`YOUR_PUBLIC_IPV4` заменяется адресом вашего сервера. Для домена сначала
направьте его DNS на сервер; поддерживается `--host your-domain.example`.

Откройте персональную HTTPS-ссылку, которую напечатает терминал. В мастере
задайте администратора, часовой пояс и токены выбранных ботов. hCaptcha можно
подключить дополнительно. Если бот уже работает в другом сервисе, перенос
webhook требует отдельного подтверждения в мастере. После завершения панель
доступна по `/GitRePosted/control/`, а мастер закрывается.

После мастера добавьте своего бота администратором нужных каналов с правом
публикации. В каждом боте откройте «Добавить канал» и перешлите публикацию из
каждого канала, чтобы подтвердить доступ. Для Telegram ↔ МАКС свяжите аккаунты
через «Связь аккаунтов», затем выберите источник и получателей в
«Создать пересылку». Эти шаги подробно разобраны в инструкции ниже.

Свой домен подключается на первом шаге мастера после настройки A-записи DNS
на IPv4 сервера; DNS меняет владелец домена. HTTPS и webhook готовит установщик.
Выберите домен до запуска финальной установки. Кнопки смены домена после
завершения пока нет; повторный `--host` готовую установку не перенастраивает.

Подробнее: [пошаговая установка](docs/INSTALLATION.md),
[настройки](docs/CONFIGURATION.md), [обслуживание](docs/OPERATIONS.md),
[безопасность](docs/SECURITY.md), [проверки](docs/TESTING.md).

## GitRePosted и GitPosted на одном сервере

Начиная с **0.1.0-rc.8**, новые установки обоих проектов используют постоянные
пути `/GitPosted/` и `/GitRePosted/`. Можно начать с любого проекта: полностью
завершите его браузерный мастер, затем установите второй.

| Размещение | GitPosted | GitRePosted |
|---|---|---|
| Общий IP без домена | `https://IP/GitPosted/control/` | `https://IP/GitRePosted/control/` |
| Общий домен | `https://example.org/GitPosted/control/` | `https://example.org/GitRePosted/control/` |
| Разные домены | `https://posted.example.org/GitPosted/control/` | `https://reposted.example.org/GitRePosted/control/` |

`IP` и домены в таблице замените своими. Без `--host` первая установка выбирает
публичный IP. Вторая без `--host` использует текущий проверенный адрес первого
проекта. Для разных доменов передайте каждому свой `--host`; для общего домена
укажите одинаковое имя либо не передавайте его второй установке. Все выбранные
имена должны иметь A-запись на IPv4 сервера. Установщик не меняет DNS.

Команды для общего IP или наследования адреса:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitPosted/main/install.sh | sudo bash
```

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitRePosted/main/install.sh | sudo bash
```

Для домена добавьте к нужной команде `-s -- --host example.org` после `sudo bash`.
Для разных доменов укажите разные имена. Для предварительной проверки добавьте
`--dry-run`: она проверяет совместимость, но не заменяет установку зависимостей.

Главная `/` показывает ссылки на размещённые на этом адресе приложения.
У каждого проекта свой мастер (`/GitPosted/install/` или `/GitRePosted/install/`),
логин, пароль и админка. Персональная ссылка одного проекта не открывает другой.
Токены ботов должны быть разными; в каналы можно добавить обоих ботов с нужными
правами. Telegram и МАКС можно пропустить и подключить позже.

nginx, MySQL и PHP общие; базы `GitPosted`/`GitRePosted`, системные пользователи,
данные, конфигурации, cookies и службы приложений разделены. Один HTTPS-сертификат
общего адреса обслуживается установщиком, который первым занял этот адрес;
второй использует его. Продление выполняется автоматически. Приложения слушают
только внутренние порты, снаружи доступны через общий nginx.

Установщик проверяет соседний проект и использует общую блокировку. При
`SHARED_INSTALL_BUSY` дождитесь другого системного шага. При прерывании
продолжайте именно свой проект через `--resume`, а браузерное задание — в его
мастере. Не удаляйте state-файлы, блокировки и базы для обхода проверки.
Сторонние сайты или произвольная существующая MySQL этим режимом не подхватываются.

**Старые установки rc.7 и ниже:** корневые адреса `/control/` сохраняются.
Повторный загрузчик не обновляет и не переносит готовое приложение. Рядом с
проверенной старой установкой второй проект требует отдельный явный домен и
тоже использует прежний корневой режим. Общий адрес с постоянными путями
предназначен для двух новых установок rc.8 и новее; автоматической миграции
готовых установок в этом выпуске нет.

## Доставка публикаций

События сначала сохраняются в MySQL, затем обрабатываются очередью. Сервис
сохраняет идентификаторы доставленных сообщений и не должен повторять уже
завершённые части публикации. Неоднозначный ответ провайдера помечается
`uncertain` и автоматически повторно не отправляется: сначала оператор
проверяет целевой канал. Очередь не гарантирует доставку при отсутствии прав,
удалении исходного сообщения или ограничениях провайдера.

Стандартная установка использует облачный Telegram Bot API. Локальный Bot API
не устанавливается мастером; его ручная настройка — отдельная задача. Личные
аккаунты Telegram и вход по номеру установщику не нужны.

## Разработка и лицензия

Runtime — Node.js ESM и MySQL. Web-мастер использует PHP, а системные операции
выполняет отдельный Python broker. В публичном комплекте нет токенов,
пользовательской базы, готовых маршрутов или серверных сессий.
